# Q2 Launcher

A modern launcher for Quake II, built around the [r1q2](https://www.r1ch.net/projects/r1q2)
client. Windows first, nothing Windows-only by design.

**Status: step 1 — the shell.** The window, the installation library and the launch
path work. Configuration, downloading the game, mods and asset packs are declared
as modules and visible in the UI, but not implemented yet. See
[docs/ROADMAP.md](docs/ROADMAP.md).

## What works today

- **Installation management** — add an existing folder, search the PC for one
  (Steam, GOG, Epic, classic paths, plus an optional deep scan of your drives),
  or create a new installation folder. Rename, reorder, favourite, relocate and
  remove.
- **Validation with a way out** — every installation is checked (does `baseq2`
  exist, is `pak0.pak` there and the retail size, is there a client executable, is
  the folder writable) and every failed check offers the action that fixes it.
- **Engine detection** — r1q2, Q2PRO, Yamagi, KMQuake II, vkQuake2, Q2RTX, the
  original client and the 2023 remaster are told apart on disk.
- **Launching** — builds the command line, starts the game, tracks the process and
  records play time.
- **The shell** — custom window chrome, the installation rail, key-art stage,
  and an action bar with a download readout the install module can drive.

## Getting started

```bash
npm install
npm run dev
```

Requires Node 22+. `npm install` downloads an Electron binary (~100 MB) on first
run.

### Scripts

| script                | what it does                                                        |
| --------------------- | ------------------------------------------------------------------- |
| `npm run dev`         | Vite dev server + Electron, with hot reload                         |
| `npm run build`       | builds main, preload and renderer into `out/`                       |
| `npm start`           | runs the built output without packaging                             |
| `npm run typecheck`   | `tsc -b` over both TS projects                                      |
| `npm test`            | Vitest unit tests                                                   |
| `npm run format`      | Prettier                                                            |
| `npm run icon`        | regenerates `build/icon.{png,ico}` from `scripts/generate-icon.mjs` |
| `npm run package:win` | typecheck, build, then an NSIS installer + zip in `release/`        |

## Layout

```
src/
  shared/          contract shared by all three processes - no node, no DOM
    ipc.ts         every channel, its request and its response type
    types/         domain model (installation, engine, job, module, settings)
    modules/       one contract file per module
  main/            Electron main process
    ipc/           one registrar per domain, all typed against shared/ipc.ts
    services/      installations, inspector, detection, launch, jobs, state
    modules/       main-process half of each module + the registry
  preload/         the single contextBridge surface, with a channel allowlist
  renderer/src/    React app
    components/    shell/, ui/, installations/
    views/         one per route
    modules/       renderer half of each module + the registry
    styles/        design tokens and the signature surfaces
    i18n/          locale bundles - all user-visible text lives here
```

Two TypeScript projects: `tsconfig.node.json` (main, preload, shared) and
`tsconfig.web.json` (renderer, shared). `src/shared` is compiled into both, which
is why nothing in it may import `node:*`, `electron` or touch the DOM.

## Design

Dark industrial steel, the amber of the Quake II logo as the one accent, Strogg
green for status and telemetry. Condensed uppercase display type (Oswald), Inter
for reading, JetBrains Mono for paths and numbers.

There are no image assets. Every surface — the app backdrop, the panels, the
rivets, the hazard stripes, the key-art stage — is CSS and inline SVG. The app
icon is generated by a committed script. See
[`src/renderer/src/styles/`](src/renderer/src/styles/).

## Security posture

`contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`. The renderer
can reach exactly the channels listed in `src/shared/ipc.ts` and nothing else —
the preload bridge enforces that allowlist at runtime. A Content-Security-Policy
is applied as a response header (strict in production, relaxed only for the dev
server). Navigation and popups are blocked, permission requests are denied, and
paths coming from the renderer are validated in main rather than trusted.

## Contributing

The repository is English throughout — code, comments, commits, docs. The UI is
translated: strings live in `src/renderer/src/i18n/locales/`, and the main process
sends i18n keys rather than prose. Only `en` ships today.

Adding a feature module is a five-step checklist that does not touch the shell —
see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#adding-a-module).
