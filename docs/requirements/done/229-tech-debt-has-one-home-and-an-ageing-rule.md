## Requirement

As the maintainer I want to see an area's open defects before touching it, and I want a
follow-up to be promoted to a story or deleted before it is rediscovered at a later gate, so that
sprint reviews stop re-listing the same items and the roadmap stays one screen.

Today ([review 2026-10-01](../../reviews/2026-10-01-codebase-review.md), F24): docs/ROADMAP.md
"Follow-ups worth doing" holds 34 bullets, five older than six weeks; the four red flows appear
three times; 12 source links are broken (`../sprints/S27/…` resolves outside `docs/`). Sprint
reviews carry "Unfixed minor review findings" paragraphs (S30 ~25 items, S29 ~15, S31 6) that
never reach the roadmap; docs/README.md gives no ageing or escalation rule, and `/sprint` says
"anything bigger is a story proposal for the review's findings section" — where it then stays.

## Decisions (Sprint)

- **(User)** Q1: Rows are removed from TECH-DEBT.md when done; git is the history.
- **(User)** AC4: Ageing rule goes into docs/README.md and `.claude/ai-scrum.md` Notes (plugin files are managed, not edited); add a follow-up "upstream the rule into the ai-scrum plugin" for the user.
- **D-a** Split between the two homes: `TECH-DEBT.md` holds defects and debt in existing code
  (bugs, untested paths, unverified assumptions, structural debt); the roadmap's "Follow-ups worth
  doing" keeps only small non-defect to-dos (a check to run, a dated chore, a feature idea) —
  reason: "see an area's open defects before touching it" needs every defect in one file, and
  that same split is what gets the follow-up list down to ≤ 10 lines.
- **D-b** Row format: a markdown table `| id | since | area | sev | item | source |`, ids
  `TD-NNN` with a `Next id: TD-NNN` line above the table, `since` = `SNN`, `sev` ∈
  `high`/`med`/`low` (the review's scale), `source` a relative link from `docs/` — reason: the
  AC's six fields, machine-checkable, and a next-id line so a removed row's id is never reused.
- **D-c** `since` for the review's not-storied findings is `S31` (the codebase state the review
  read); for roadmap follow-ups and review leftovers it is the sprint of their source review; an
  item with no source gets `S33` and links the codebase review's findings section (F24) — reason:
  ageing needs a sprint on every row and the review is where undated items were surfaced as debt.
- **D-d** Overdue means `current − since > 3`, where current is the highest `SNN` directory under
  `docs/sprints/` or `docs/sprints/done/` — reason: AC4's "older than three sprints", computed
  from the repo instead of a hand-maintained number.
- **D-e** `scripts/check-docs.mjs` fails `npm test` on a malformed `TECH-DEBT.md` row (missing
  field, bad `since`/`sev`, duplicate id, id ≥ next id, unresolved source link) but never on age;
  overdue rows are listed by `node scripts/check-docs.mjs --overdue` (exit 0) — reason: a gate
  that turns red because a calendar moved would break unrelated stories' builds mid-sprint.
- **D-f** `/roadmap check` *reports* overdue `TECH-DEBT.md` rows and leaves promoting/deleting
  them to the maintainer, while overdue roadmap follow-ups keep the plugin's existing automatic
  promote-or-delete — reason: AC4 says "reports", and silently deleting a known defect loses the
  information the file exists to keep.
- **D-g** The README pointer and rule go under docs/README.md's `## Project-specific` section, as
  "Where do I find…" bullets that state they override the generated bullets above — reason: the
  top of that file is regenerated by `/ai-scrum:setup` and only `## Project-specific` survives.
- **D-h** Triage defaults to a `TECH-DEBT.md` row or deletion; a new story draft only for an item
  that needs a decision or more than one deliverable, with the next free id from
  `docs/requirements/` + `done/INDEX.md` at build time — reason: drafts carry decisions the user
  must make, and fewer drafts avoid id collisions with concurrent stories.
- **D-i** The "34 follow-ups" is the review's snapshot; the triage covers the list as it stands
  when 229 is built (S32 already removed some, S32/S33 may have added some) plus the S27–S31
  reviews' unfixed paragraphs — reason: triaging lines that no longer exist is meaningless, and
  missing newer lines would leave the list over budget.
- **D-j** AC3's broken roadmap links are expected to be fixed by story 227 (its AC5 makes every
  `docs/**` link resolve, built earlier in S33); 229 only keeps them green and adds `TECH-DEBT.md`
  — reason: no double work, and 227's link check already covers `docs/**` by glob.
- **D-k** AC5's suggested cut is the cut actually applied (S32 = 11.1, S33 = 11.2), linking the
  review for its original five-group suggestion; the S32 review's drafts 232–236 move from the
  follow-up list into that same row — reason: the applied cut is the true state, and drafts
  awaiting a decision belong under "Open / unprioritised", not follow-ups.
- **D-l** AC2's completeness (every source item has a destination, every deletion a reason) is
  proven by a triage ledger in this story's `## Done` (one line per item → row id / draft id /
  "deleted: reason") that the deletion reasons in the commit message mirror, checked by the
  default review; the measurable part (≤ 10 lines, no link to a story 199–231) is a unit test —
  reason: it is a one-off content migration with no runtime behaviour, and the ledger makes the
  review a mechanical comparison rather than a judgement.
