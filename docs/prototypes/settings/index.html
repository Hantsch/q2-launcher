Settings view — design test

The current Settings tab renders every cvar as a full-width card. That is roughly 130 px of vertical space per setting, so 30 settings become five screens of scrolling — and every one of them looks equally important.

  • Repetition beats signal. CURRENT VALUE / RECOMMENDED DEFAULT is printed 30 times, as two labelled lines each. Nothing shows at a glance which settings actually deviate.
  • "NO ENGINE FACTS" on every row. One profile-level fact, repeated 30 times. It belongs in the header strip that already says it once.
  • Controls are 1200 px wide. A text field for rate and a dropdown with 3 options do not need the whole window.
  • Toggle rows have a hole. The control grid keeps an empty cell where the input would be, which is why cl_run and vid_fullscreen are the tallest rows on the page.
  • Descriptions are permanent. Useful once, noise forever.
A

Dense rows

Same list, ~44 px per row: label + cvar name, capped 250 px control, one mono value/default column, flame bar for "changed". Description collapses to one line and expands on hover. Badges only when there is something to say.

 open → B

Setting tiles

Uses the width: auto-fill tile grid, 3–4 per row. Toggles are half-height tiles. Summary strip on top (changed / out of range / engine notes), flame top edge marks a deviation.

 open → C

Rail + inspector

Group rail left, one-line-per-setting list in the middle, everything explanatory in a right inspector for the selected row. All 30 settings fit on one screen; scales to 100+.
